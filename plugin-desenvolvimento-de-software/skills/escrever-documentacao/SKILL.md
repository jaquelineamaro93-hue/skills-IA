# Escrever documentação

Escreve documentação técnica clara e fácil de manter, para públicos e objetivos diferentes.

## Tipos de documento

### README
- O que é e por que existe
- Começo rápido (menos de 5 minutos para funcionar)
- Configuração e uso
- Como contribuir

### Documentação de API
- Cada endpoint com exemplo de pedido e resposta
- Autenticação e códigos de erro
- Limites de uso e paginação
- Exemplos com SDK

### Roteiro de operação (runbook)
- Quando usar este roteiro
- O que é preciso antes e quais acessos
- Passo a passo
- Como voltar atrás
- A quem escalar

### Documento de arquitetura
- Contexto e objetivos
- Visão geral com diagramas
- Principais decisões e prós e contras
- Caminho dos dados e pontos de integração

### Guia para quem está chegando
- Como montar o ambiente
- Principais sistemas e como se ligam
- Tarefas comuns com passo a passo
- A quem perguntar o quê

## Princípios

1. **Escreva para quem vai ler.** Quem é e do que precisa?
2. **Comece pelo mais útil.** Não esconda o principal.
3. **Mostre, não só diga.** Exemplos de código, comandos, prints.
4. **Mantenha atualizado.** Documentação velha é pior que nenhuma.
5. **Faça link, não copie.** Aponte para outros documentos em vez de repetir.
